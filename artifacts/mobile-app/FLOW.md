# Android — how execution travels

Where control actually goes on Android, and which file to open when a step
misbehaves. Repo-wide flow (the request pipeline, the SPA boot) is in the root
`FLOW.md`; this is the native half.

---

## 1. Launch

```
tap the launcher icon
  └─ MainActivity                       android/app/src/main/java/.../MainActivity.java
      └─ Capacitor Bridge starts a WebView
          ├─ reads android/app/src/main/assets/capacitor.config.json
          │    (generated by `cap sync` from capacitor.config.ts — never edit it)
          └─ loads https://localhost/index.html
               from android/app/src/main/assets/public/
               (the SPA, copied in by `cap sync` — gitignored, it is build output)
                  └─ App.tsx
                      ├─ ThemeProvider
                      ├─ NativeShell        ← registers the listeners below
                      └─ AppLockGate → routes
```

The splash stays up through all of this: `launchAutoHide: false` in
`capacitor.config.ts`, dismissed by `dismissSplash()` once React has painted. A
timer instead would either flash it away before the first paint or hold it after
the app is ready, depending on how fast the handset is.

**If the app opens to a white screen**, the bundle is missing or stale — run
`cap sync` after building the portal.

## 2. The back button

```
hardware/gesture back
  └─ CapacitorApp "backButton" listener      practice-portal/src/lib/native.ts
      ├─ canGoBack → window.history.back()
      └─ otherwise → CapacitorApp.exitApp()
```

A WebView's default is "go back in history, and if there is none, do nothing",
which strands the user on their first screen with no way out but the task
switcher. Exiting at the root is what Android users expect.

## 3. Sign-in

Two shapes, and only one of them leaves the app.

### Email or SMS code — stays inside

```
portal-sign-in.tsx → session.tsx
  └─ signIn.emailCode.sendCode()  /  signIn.phoneCode.sendCode()
      └─ code arrives out of band, typed into the same screen
          └─ verifyCode() → leg.finalize() → setLocation("/dashboard")
```

No native involvement at all.

### Google or Zoho — leaves and comes back

```
session.tsx  signIn.sso({ redirectUrl, redirectCallbackUrl })
  │            both built from authRedirectBase() — lib/platform.ts
  │            which returns "in.lexpractice.app://" when isNative()
  ▼
Capacitor sees a navigation to a host NOT in allowNavigation ([] — empty)
  └─ hands it to a Custom Tab (the system browser)
      └─ Google consent screen
          └─ redirects to Clerk
              └─ Clerk redirects to in.lexpractice.app://portal/callback
                  ▼
AndroidManifest.xml  <intent-filter> scheme="in.lexpractice.app"
  └─ Android routes it to MainActivity
      (launchMode="singleTask" — the RUNNING one, not a new copy)
          └─ CapacitorApp "appUrlOpen"        lib/native.ts
              └─ setLocation("/portal/callback?…")
                  └─ <AuthenticateWithRedirectCallback> completes the handshake
```

The empty `allowNavigation` is what forces step 2. See `DECISIONS.md`.

**If sign-in returns to a fresh app with no session**, check `launchMode`.
**If Clerk refuses before Google appears**, the scheme is missing from Clerk's
allowed redirect URLs.

## 4. Talking to the API

```
any query/mutation
  └─ customFetch                     lib/api-client-react/src/custom-fetch.ts
      ├─ setBaseUrl(VITE_API_BASE_URL)      ← absolute, because the WebView's
      │                                       own origin is https://localhost
      ├─ Authorization: Bearer <Clerk JWT>  ← useApiAuthBridge; a cookie would
      │                                       never be sent cross-origin
      └─ X-Workspace-Id / X-Workspace-Token ← lib/workspace-context.ts
```

None of this is Android-specific code — it is the existing split-hosting path,
which the app happens to satisfy by construction.

**If every request 401s**, the bundle was built without `VITE_API_BASE_URL`.
**If every request is blocked by CORS**, `https://localhost` is missing from the
API's `CORS_ALLOWED_ORIGINS`.

## 5. Photographing a document

```
documents.tsx  "Photograph"
  └─ captureDocument()               practice-portal/src/lib/native-files.ts
      └─ Camera.getPhoto({ resultType: Uri, allowEditing: true })
          └─ CAMERA runtime permission, first time only
              └─ webPath (a local file:// URI the WebView can read)
                  └─ fetch(webPath).blob()  → re-typed to image/jpeg
                      └─ new File([blob], "capture-….jpg", { type })
                          └─ the SAME submitUpload() the file picker feeds
                              └─ POST /api/cases/:id/documents/content
                                 raw body, metadata in headers
```

Three server rules the client has to respect, all enforced in `blob-store.ts`:
JPEG (HEIC is not on the allowlist), a declared `Content-Type` that matches the
magic bytes, and raw bytes rather than base64.

## 6. A notification, end to end

```
SERVER                                        DEVICE
──────                                        ──────
reminder-scheduler.ts  (node-cron, 30 min)
  ├─ task deadlines      T-24h / T-2h
  ├─ consultations       T-24h / T-2h
  └─ calendar entries    today / tomorrow
       fanned out over `audience`
        │
        ▼
   notify()              lib/notify.ts
     ├─ notifications row  (always — also the dedup key)
     ├─ sendMail()         (if they have a verified address)
     └─ sendPush()         lib/push.ts
          └─ device_tokens WHERE workspace_id = … AND user_id = …
             ▲ the tenant boundary; a device row exists per chamber
          └─ push_outbox → FCM HTTP v1
                            │
                            ▼
                                              Firebase → the handset
                                                └─ system notification
                                                    └─ tapped
                                                        └─ pushNotificationActionPerformed
                                                           lib/native-push.ts
                                                            └─ data.link, if it
                                                               starts with "/"
                                                                └─ setLocation(link)
```

Registration runs the other way: **Settings → Turn on** →
`PushNotifications.register()` → the OS returns a token → `POST /api/devices`,
which writes it against the caller's **active workspace** taken from the session,
never from the body.

The outbox is drained every minute beside the mail outbox, with the same backoff
ladder — a failed hearing reminder has to stay visible rather than becoming a log
line.

**With no `FCM_SERVICE_ACCOUNT_JSON`**, messages are still recorded, marked
`suppressed`, and never sent. `/api/readyz` reports `pushConfigured`.

## 7. The app lock

```
app goes to the background
  └─ CapacitorApp "appStateChange" (isActive false)   components/app-lock.tsx
      └─ remember the timestamp
app returns
  └─ elapsed >= grace (90s default) → locked = true
      └─ overlay renders ABOVE the router; children stay mounted but blurred
          (unmounting would throw away every cached query and in-progress form)
              └─ BiometricAuth.authenticate({ allowDeviceCredential: true })
                  ├─ success → locked = false
                  └─ anything else → the overlay stays, offering sign-out
```

It is a UX control, not a security boundary — the session token is still in the
WebView. See the root `DECISIONS.md`.
