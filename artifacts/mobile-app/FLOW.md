# iOS — how execution travels

Where control actually goes on iOS, and which file to open when a step
misbehaves. Repo-wide flow (the request pipeline, the SPA boot) is in the root
`FLOW.md`; this is the native half.

---

## 1. Launch

```
tap the icon
  └─ AppDelegate → SceneDelegate                ios/App/App/
      └─ CAPBridgeViewController (Main.storyboard)
          └─ WKWebView
              ├─ reads ios/App/App/capacitor.config.json
              │    (generated by `cap sync` from capacitor.config.ts — never edit it)
              └─ loads capacitor://localhost/index.html
                   from ios/App/App/public/
                   (the SPA, copied in by `cap sync` — gitignored, it is build output)
                      └─ App.tsx
                          ├─ ThemeProvider
                          ├─ NativeShell        ← registers the listeners below
                          └─ AppLockGate → routes
```

Note the scheme: **`capacitor://localhost`**, where Android uses
`https://localhost`. Both must appear in the API's `CORS_ALLOWED_ORIGINS`.

The splash stays up through all of this: `launchAutoHide: false` in
`capacitor.config.ts`, dismissed by `dismissSplash()` once React has painted.

**If the app opens to a white screen**, the bundle is missing or stale — run
`cap sync` after building the portal.
**If it opens to a blank page after a plugin change**, `pod install` was not
re-run.

## 2. Status bar and safe areas

```
ThemeProvider resolves light/dark
  └─ applyNativeTheme()                practice-portal/src/lib/native.ts
      └─ StatusBar.setStyle({ Style.Light | Style.Dark })
```

`Style.Light` means light **content** on a dark bar — the opposite of what the
name suggests, and the usual cause of an unreadable clock. iOS draws _under_ the
status bar rather than painting one, so unlike Android there is no background
colour to set.

The layout keeps clear of the notch through `contentInset: "always"` plus the
`*-safe` utilities in `index.css`. Both are needed; see `DECISIONS.md`.

## 3. Sign-in

Two shapes, and only one of them leaves the app.

### Email or SMS code — stays inside

```
portal-sign-in.tsx → session.tsx
  └─ signIn.emailCode.sendCode()  /  signIn.phoneCode.sendCode()
      └─ code arrives out of band, typed into the same screen
          └─ verifyCode() → leg.finalize() → setLocation("/dashboard")
```

No native involvement at all. An SMS code autofills from the keyboard bar,
because the input carries `autoComplete="one-time-code"`.

### Google or Zoho — leaves and comes back

```
session.tsx  signIn.sso({ redirectUrl, redirectCallbackUrl })
  │            both built from authRedirectBase() — lib/platform.ts
  │            which returns "in.lexpractice.app://" when isNative()
  ▼
Capacitor sees a navigation to a host NOT in allowNavigation ([] — empty)
  └─ opens SFSafariViewController
      └─ Google consent screen
          └─ redirects to Clerk
              └─ Clerk redirects to in.lexpractice.app://portal/callback
                  ▼
Info.plist  CFBundleURLTypes → the scheme is ours
  └─ iOS reopens the app with that URL
      └─ CapacitorApp "appUrlOpen"        lib/native.ts
          └─ setLocation("/portal/callback?…")
              └─ <AuthenticateWithRedirectCallback> completes the handshake
```

**If Clerk refuses before Google appears**, the scheme is missing from Clerk's
allowed redirect URLs.
**If the browser sheet opens and never returns**, `CFBundleURLTypes` is missing
or the scheme does not match `APP_URL_SCHEME` in `lib/platform.ts`.

## 4. Talking to the API

```
any query/mutation
  └─ customFetch                     lib/api-client-react/src/custom-fetch.ts
      ├─ setBaseUrl(VITE_API_BASE_URL)      ← absolute, because the webview's
      │                                       own origin is capacitor://localhost
      ├─ Authorization: Bearer <Clerk JWT>  ← useApiAuthBridge; a cookie would
      │                                       never be sent cross-origin
      └─ X-Workspace-Id / X-Workspace-Token ← lib/workspace-context.ts
```

None of this is iOS-specific code — it is the existing split-hosting path, which
the app happens to satisfy by construction.

**If every request 401s**, the bundle was built without `VITE_API_BASE_URL`.
**If every request is blocked by CORS**, `capacitor://localhost` is missing from
the API's `CORS_ALLOWED_ORIGINS` — note it is a _different_ origin from Android's.

### The one request that outlives the foreground

`POST /cases/:id/drafts` awaits the model call, so it is held open for a minute
or more — far longer than anything else the app sends. **iOS is the harsher of
the two platforms here.** Backgrounding the app suspends the `WKWebView`
process, which is not a throttle like Android's Doze: the URLSession task
backing that fetch is torn down, and it does not resume when the app does. A
wifi-to-cellular handoff ends it as well.

The server does not care. `runDraft` writes the `drafts` row in `generating`
**before** it calls the model, and sets `ready` or `failed` itself, so the work
completes regardless of who is still listening. Recovery is TanStack Query's
default `refetchOnWindowFocus`: resuming the app refetches the drafts list, the
row is there, and if it is still `generating` the page's own 2-second poll takes
over.

**The symptom to recognise:** "Lost the connection — the draft may still be
running." That toast means the socket went, not that the draft did. Running it
again spends the chamber's AI budget on a draft that is already being written.

Since the whole point is that the reader has left the app, a completion push
would be the natural pairing — `notify()` is right there. It is deliberately not
wired up: the request being synchronous means the draft usually lands while
somebody is watching it, and a notification for that is clutter. It becomes the
right call the day the POST returns 202. See the root `DECISIONS.md`.

## 5. Photographing a document

```
documents.tsx  "Photograph"
  └─ captureDocument()               practice-portal/src/lib/native-files.ts
      └─ Camera.getPhoto({ resultType: Uri, allowEditing: true })
          └─ NSCameraUsageDescription prompt, first time only
              └─ webPath (a local URI the webview can read)
                  └─ fetch(webPath).blob()  → re-typed to image/jpeg
                      └─ new File([blob], "capture-….jpg", { type })
                          └─ the SAME submitUpload() the file picker feeds
                              └─ POST /api/cases/:id/documents/content
                                 raw body, metadata in headers
```

**The iOS-specific hazard is HEIC.** An iPhone captures HEIC by default, and the
server's MIME allowlist (`blob-store.ts`) does not include it — an untouched
capture comes back `415`. The plugin is asked for JPEG and the blob is re-typed
before upload, because the server also sniffs magic bytes and refuses a body
whose content disagrees with the declared `Content-Type`.

Going out the other way, `documents.tsx` writes the file to the Cache directory
and opens the **share sheet** — the web page's object-URL anchor click does
nothing in a webview, since there is no download manager behind it.

## 6. A notification, end to end

```
SERVER                                        DEVICE
──────                                        ──────
reminder-scheduler.ts  (node-cron, 30 min)
  ├─ task deadlines      T-24h / T-2h
  ├─ consultations       T-24h / T-2h
  └─ calendar entries    today / tomorrow
       fanned out over `audience`
        │
        ▼
   notify()              lib/notify.ts
     ├─ notifications row  (always — also the dedup key)
     ├─ sendMail()         (if they have a verified address)
     └─ sendPush()         lib/push.ts
          └─ device_tokens WHERE workspace_id = … AND user_id = …
             ▲ the tenant boundary; a device row exists per chamber
          └─ push_outbox → FCM HTTP v1
                            │
                            ▼
                        Firebase → APNs → the handset
                        ▲ this hop needs the .p8 key uploaded to
                          Firebase; the server never speaks APNs
                                                └─ tapped
                                                    └─ pushNotificationActionPerformed
                                                       lib/native-push.ts
                                                        └─ data.link, if it
                                                           starts with "/"
                                                            └─ setLocation(link)
```

Registration runs the other way: **Settings → Turn on** →
`PushNotifications.register()` → APNs returns a token, which Firebase maps →
`POST /api/devices`, which writes it against the caller's **active workspace**
taken from the session, never from the body.

**If Android notifications arrive and iOS ones do not**, check the APNs key
upload in Firebase before suspecting the app — that hop is the only part of the
path that is iOS-only.

**With no `FCM_SERVICE_ACCOUNT_JSON`**, messages are still recorded, marked
`suppressed`, and never sent. `/api/readyz` reports `pushConfigured`.

## 7. The app lock

```
app goes to the background
  └─ CapacitorApp "appStateChange" (isActive false)   components/app-lock.tsx
      └─ remember the timestamp
app returns
  └─ elapsed >= grace (90s default) → locked = true
      └─ overlay renders ABOVE the router; children stay mounted but blurred
          (unmounting would throw away every cached query and in-progress form)
              └─ BiometricAuth.authenticate({ allowDeviceCredential: true })
                  ├─ Face ID / Touch ID, falling back to the device passcode
                  ├─ success → locked = false
                  └─ anything else → the overlay stays, offering sign-out
```

The passcode fallback matters more than it looks: Face ID fails repeatedly behind
a mask or with wet hands, and without a fallback the only way back into the app
would be to reinstall it.

It is a UX control, not a security boundary — the session token is still in the
webview. See the root `DECISIONS.md`.
